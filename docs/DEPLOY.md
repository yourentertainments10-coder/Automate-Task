# Deploying CarTrends CRM — Render + Neon

One Render web service serves **both** the Django API and the built React
app (WhiteNoise). One URL, no CORS setup, free tier works.

## Steps to go live (in order)

1. **Commit & push** (review `git status` first — `.env` must show as
   untracked/ignored, never staged):
   ```
   git add -A
   git commit -m "Phase C + deployment config"
   git push origin main
   ```

2. **Render dashboard** → New → **Blueprint** → connect the
   `Automate-Task` GitHub repo. Render reads `render.yaml` automatically.

3. When it asks for env vars, paste **DATABASE_URL** = the Neon connection
   string (Neon dashboard → your project → Connect → copy the URI ending
   in `?sslmode=require`). Everything else is pre-filled by the blueprint.

4. If Render assigns a different service name/URL, update these three env
   vars in the dashboard to the real URL: `ALLOWED_HOSTS`,
   `CSRF_TRUSTED_ORIGINS`, `CORS_ORIGINS`.

5. First deploy takes ~5–8 min (npm build + pip install + migrate).
   Check `https://<your-app>.onrender.com/health` → `{"status": "ok"}`.

6. Log in with the same accounts as local (data was copied as-is).

## Known free-tier limits (tell the reviewer)

- **Cold start**: the service sleeps after ~15 min idle; first request
  takes ~50s to wake. Normal for free tier.
- **Uploaded files are ephemeral**: task attachments / lead documents
  disappear on every redeploy (Render free has no persistent disk).
  Fine for UAT; for production, add a Render disk (paid) or S3 later.
- **In-process reminder ticker** only runs while the service is awake.

## Security notes

- `SECRET_KEY` is generated by Render (`generateValue: true`) — the dev
  key is never used in production.
- The Neon `DATABASE_URL` lives in exactly two places: Neon's dashboard
  and Render's env vars. Never in git, never in the frontend.
- Demo passwords (`username@12345`) are weak — before real company data
  goes in, change them (HR → Users, or `manage.py changepassword`).

## Local dev after this change

Nothing changes: local runs on SQLite as before. To deliberately point
local dev at the live Neon DB (rarely needed), uncomment `DATABASE_URL`
in `backend/.env` — and remember every local experiment then touches the
live database.
